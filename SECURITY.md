# Privacy and security reports

Never post a secret, private conversation, personal document or full diagnostic dump in a public issue. For a suspected leak, report only the affected public path and general issue type, without repeating the sensitive value. Use an available private reporting channel if the repository offers one.

If you accidentally publish your own credential, revoke/rotate it through its provider. Removing a current file does not remove Git history, cached copies or forks. The included validator is a generic baseline, not a guarantee of anonymity.

The initializer does not run agents or network calls. Keep its generated workspace private. Review downloaded code and agent instructions before use; templates are conventions, not access-control enforcement.
