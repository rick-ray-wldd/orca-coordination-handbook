# 審查請求（範本）

> 所有「審查、檢查、找問題、核對」類派工使用。審查者**只讀**。

```
【審查任務】<T-EXAMPLE0000>｜審查 <產物名稱>
【請求者】<督導總控>　【審查者】<核對總控，或其派出的唯讀審查者>

【審查對象（版本綁定）】
- 路徑：<receipts/.../REPORT.md、PROJECT_ROOT/...>
- 版本：sha256=<...> 或 commit <...>
- 若審查期間發現檔案 hash 已變，停止並回報，不要審新版本

【User 原始需求與成功條件】
<原文照貼，讓審查者對照>

【審查重點】
1. <是否達到每一條成功條件>
2. <正確性：…>
3. <安全與隱私：有無私人資料外洩、有無對外動作>
4. <範圍：writer 是否改了可寫範圍以外的檔案>

【規則】
- 只讀：不得修改被審查的檔案或資料；不得執行對外動作
- 不啟動其他代理或終端；最大併發 1；只用既有訂閱
- 每個問題含：位置、嚴重度（高／中／低）、證據、建議
- 沒有找到問題就直接說「未發現問題」，不湊數
- 用 review-report 格式交付，放到 <receipts/.../REVIEW.md>
- 完成後回報自己的站台
```
