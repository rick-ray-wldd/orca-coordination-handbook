# 派工訊息（範本）

> 督導總控每次 ②③④⑤ 派工時使用。整段貼給 writer。不要刪欄位；不適用就寫「無」。

```
【任務】<T-EXAMPLE0000>｜<一句話標題>
【督導】<A 或 B>　【核對】<另一位>　【User 決策紀錄】<無 或 D-EXAMPLE-00>

【User 原始需求】
<原文照貼，不改寫>

【成功條件（可驗收）】
1. <可觀察的結果，例如：首頁顯示三場活動>
2. <品質條件，例如：手機 375px 與桌面 1280px 不跑版>
3. <測試條件，例如：既有測試全過，新增測試覆蓋新元件>

【可讀】<PROJECT_ROOT/...>
【可寫】<只列必要的資料夾>；交付證據放 <HUB_ROOT/receipts/<主題>-<日期>/>
【禁止（預設）】部署、push、合併主分支、寄信、傳訊息給外部、公開分享、付款、建立帳號、修改全域設定、修改其他專案、<其他>
【例外授權】<若 User 已對某一次對外動作有具體、可追溯的授權，在此列出：動作、範圍、授權來源；未列出者一律禁止>
【資料界線】<可用的模型範圍；不得把哪些資料送出本機>

【終端與代理】
- 可否開新終端：<否>
- 可否啟動其他代理：<否／最多 N 個唯讀審查者>
- 最大併發：<1>
- 額度上限：<只用既有訂閱；零新增支出>

【交付證據（必附）】
- 測試指令與輸出
- 產物路徑與 SHA-256（或 commit）
- <截圖／逐頁渲染／回讀結果>

【完成後】
1. 寫卡片 comment：orca worktree set --worktree active --comment "<一句話>" --json
2. 用 station-report 格式回報自己的站台，狀態 review
3. 不要標 done；對外動作只做【例外授權】明列的那一項，其餘一律不做；範圍外的問題列在回報裡

【遇到阻塞】回報 blocked 並寫具體原因；需要 User 決定的，列出選項與建議，狀態 waiting_user
```
